# Restored V0.11 snapshot audit

This file records findings from running the archived V0.11 package. The source under `legacy/v0.11/` is retained unchanged.

## Reproduction performed

- `python -m unittest discover -s legacy/v0.11 -v`: 7 tests passed.
- `python legacy/v0.11/evaluate_v10.py`: completed.
- `python legacy/v0.11/evaluate_v11.py`: completed.
- `python legacy/v0.11/evaluate_fields.py`: completed.
- `python legacy/v0.11/evaluate_v08.py`: completed.

## Metric correctness issue

`evaluate_v11.py` assigns `truth = None` for the `step3` scenario. When the algorithm correctly rejects the unsupported step size, `ranked` is empty and `top` is `None`; the expression `top == truth` then evaluates to `True`. The stored `top_correct` count is therefore 100/100 even though the model was rejected in all 100 cases. This is not a successful identification result.

`evaluate_v10.py` has the same class of issue in its `outside` condition: `truth` can be `None`, and a rejected/empty candidate can compare equal to `None`. The `forced_correct`, `initial_retains`, and `final_retains` columns must not be interpreted as accuracy for that condition without checking the rejection state.

Correct scoring should separate at least:

- exact identification of a supported ground-truth model;
- correct rejection when the scenario is outside the supported family;
- false acceptance of an unsupported model;
- ambiguity/abstention on supported but underdetermined data.

V0.2's confirmatory benchmark uses separate `accepted`, `exact_model`, and unsupported-checksum rejection metrics rather than comparing `None` to `None`.

## Capability boundary found in the restored package

- `joint.py` and `benchmark.py` contain variable payload-length and inter-frame noise/deletion simulations, but the joint model is limited to a narrow 2-byte-sync / 1-byte length / affine byte-sum checksum family.
- `fields.py` is a standalone heuristic over already-framed messages; it does not solve the full framing problem. Its `no_wrap` field-recovery case only reached F1 0.727 in the reproduced run.
- `ambiguity.py` and `dependency.py` handle counter-width ambiguity at a known offset, not end-to-end offset discovery.
- The V0.11 README title still says V0.9 even though it documents V0.10 and V0.11 sections.
- The CRC adapter is only a wrapper around an external `reveng` executable; it is not an integrated CRC parameter search.

These findings explain why V0.2 integrates framing, validation, corruption triage, and field hypotheses while preserving the older modules for comparison.
