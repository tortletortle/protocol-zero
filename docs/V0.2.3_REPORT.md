# PROTOCOL ZERO V0.2.3 — unknown CRC-8 and behavioral equivalence

Base: V0.2.2 at `3df12548c7b6b67dbb82a82632e9e53745b18489`. Existing streaming inference and conditional repair unchanged. New separate CLI consumes independently delimited complete codewords with one trailing CRC byte; the entire preceding body is assumed covered. Non-reflected CRC-8, all 128 odd polynomials, arbitrary 8-bit init/xorout. Exact fitting only. No device transmission, no automatic correction. The existing five preset checksums are a separate comparison, not a full framing baseline.

## Method
For each polynomial, compute the zero-init CRC and XOR it with the observed trailer. By linearity, the residual must be constant across equal-length bodies. For surviving polynomials, advance all 256 initial states through the requisite number of zero bytes. One length determines xorout for each init; other lengths filter the candidate set. This searches the bounded family without enumerating 65,536 init/xorout pairs per polynomial. The validation set excludes training bodies, and requires >=6 distinct training and >=4 distinct validation bodies with >=3 distinct checksum values per split. Contradictory repeats raise an error. For a fixed polynomial, equality on the empty body and one zero byte proves equivalent behavior for all body contents and lengths (linearity, fixed difference under the one-byte transition); retain all parameter sets, group their behavior. Distinguishing templates are offline, user-supplied bodies; rank by number of separated behavior-class pairs. No-response leaves candidates intact. New observations must be clean and independently delimited; a wrong additional observation can eliminate the correct model.

## Executed results
- 34 current tests (26 inherited, 8 new), 7 legacy tests passed locally. Python compilation passed. CLI example: 256 initial parameter candidates, one behavior group after one clean observation.
- Controlled synthetic benchmark: 12 seeds (73200–73211) x 6 scenarios = 72 runs. Independent polynomial long-division generator. 12 training, 8 disjoint validation and 7 test observations of unseen sizes. 48/48 clean supported cases retained actual parameter tuple; presets matched 12/48. 36/48 had one behavior class before extra acquisition, and every retained model predicted all seven test checksums in those 36. In the 12 fixed-length cases, 256 behavior classes per case remained until acquisition. All 12 nonlinear and 12 corrupted-validation cases rejected. No wrong singleton behavior group. A deliberate length menu (8,9,263; CRC polynomial 0x1D, period 255) yields fixed-length resolution 0/12 no acquisition, 4/12 random, 0/12 longest, 12/12 planner. Not representative of arbitrary length availability.
- Exploratory follow-up: 40 fresh seeds (73300–73339), random odd polynomial and initial length 6..19; same-size train/validation, random prospective sizes in 1..512 plus initial size. Actual tuple retained 40/40; 38 initially ambiguous. One-observation resolution: random 29/38, longest 33/38, planner 38/38. Mean remaining behavior classes 16.55, 1.50, 1.00 respectively. No true tuple lost. Not a preregistered external benchmark.

## Reproduce
`python -m unittest discover -s tests -v`; `python experiments/crc_benchmark.py`; `python experiments/crc_exploratory.py`. Raw CSVs and summary JSON generated by scripts. CLI: `python -m protocol_zero.crc_discovery --train train*.bin --validation val*.bin --prospective probe.bin --observations obs.bin --out result.json` (one complete codeword per train/validation/observations file, prospective is body only). Python 3.10+, standard library.

## Boundary and prior art
CRC RevEng (https://reveng.sourceforge.io/) already performs broad CRC parameter reverse engineering; its catalogue (https://reveng.sourceforge.io/crc-catalogue/legend.htm) describes globally equivalent parameter forms. This is a bounded independent implementation with explicit behavior classes and acquisition planning, not a claim of algorithmic novelty or superiority to RevEng. No external-tool comparison, reflected CRC, CRC-16, unknown coverage, noise-tolerant fitting, raw-stream integration, real-device validation or remote CI performed. Correctness claims limited to tested synthetic conditions; clean data and a correct model family are required. A single acquired frame only refines conditionally, not a proof that hardware follows the inferred rule.
