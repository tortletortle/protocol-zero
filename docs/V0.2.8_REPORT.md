# PROTOCOL ZERO V0.2.8 — calibrated evidence, dependence audit, and abstention

## Base and scope

Base: research/v027-independent-evidence at commit
69f5534e6be00c072c77c214ff989e8c595f61b2.

V0.2.8 adds a separate reliability layer. It does not modify the existing
CRC discovery, framing, collision-witness, or V0.2.7 evidence-fusion logic.
It remains an offline analysis prototype. No device I/O, active probing,
automatic repair, or real-device validation is included.

## New implementation

protocol_zero.reliability adds:

- ReliabilityProfile: source-level TP/FP/TN/FN counts from a labelled,
  separately identified calibration dataset, scoped to a declared environment.
- calibrate_sources: builds reliability profiles and pairwise error
  dependence assessments from paired labelled source outputs.
- assess_pairwise_dependence: computes positive-class and negative-class
  error-indicator phi correlations, with approximate Fisher-z intervals.
- EvidenceObservation: one source's pass/fail/unavailable verdict for a
  candidate.
- observations_from_audit: converts V0.2.7 audit rows into one verdict per
  source. Mixed, partial, or unknown rows become unavailable, not a negative.
- evaluate_hypothesis: combines calibrated likelihood-ratio intervals and
  returns support, reject, or abstain.

### Reliability and likelihood model

For each source, calibration estimates sensitivity and specificity:

- sensitivity = TP / (TP + FN)
- specificity = TN / (TN + FP)
- FPR = 1 - specificity
- FNR = 1 - sensitivity

Wilson score intervals are calculated for sensitivity and specificity.
Bonferroni adjustment allocates the requested family-wise error budget across
the two rates for each usable source. The candidate likelihood-ratio interval
is then derived monotonically from those bounds:

- source says pass: LR = sensitivity / FPR
- source says fail: LR = FNR / specificity

The intervals are combined with a user-supplied prior under a conditional-
independence model. The result is a model-dependent posterior envelope, not a
real-world accuracy guarantee or a substitute for labelled validation.

### Fail-closed rules

- Calibration and evaluation dataset identifiers must differ.
- Calibration and evaluation environment identifiers must match. A mismatch
  makes that source unusable and leads to abstention when too few sources remain.
- At most one usable observation may contribute from a declared provenance
  group. Duplicate usable groups are rejected rather than counted twice.
- Pairwise dependence auditing is required by default. Every pair of usable
  sources must have a dependence assessment from the same calibration dataset
  and environment. Disabling the gate is an explicit ablation, not the safe
  default.
- A pair assessed as dependent, uncertain, or missing blocks the decision.
- Fewer than two usable provenance groups cannot produce a decision by default.
- Every result retains integrity_verified = false.

The dependence audit, enabled by default, uses phi correlation between paired
source error indicators, separately for valid and invalid calibration examples.
A detected large correlation blocks fusion. no_large_correlation_detected is
not proof of independence: the diagnostic is approximate and may miss
nonlinear, conditional, or time-varying dependencies. The threshold 0.25 is an
explicit engineering setting, not a universal statistical boundary.

## Synthetic benchmark

Reproduction:

    python -m pip install -e '.[robust]'
    python -m unittest discover -s tests -v
    python experiments/reliability_benchmark.py

The benchmark uses seed base 20261123, 500 valid and 500 invalid labelled
calibration examples per scenario, and 4,000 evaluation candidates per
scenario (2,000 valid, 2,000 invalid). Calibration and evaluation IDs differ.
The seven scenarios are generated, not real captures. Metrics below are from
one deterministic run per scenario.

| Scenario | Majority-vote accuracy | Calibrated coverage without dependence gate | Accuracy on decided candidates | FAR / FRR without dependence gate | Dependence-gated coverage |
|---|---:|---:|---:|---:|---:|
| Nominal sources | 99.25% | 89.10% | 99.89% | 0.20% / 0.00% | 89.10% |
| One near-random source | 96.85% | 93.45% | 99.76% | 0.25% / 0.20% | 93.45% |
| Two moderate, one weak | 89.80% | 80.20% | 98.72% | 0.95% / 1.10% | 80.20% |
| One adversarial but calibrated source | 94.12% | 83.15% | 99.97% | 0.00% / 0.05% | 83.15% |
| Known environment mismatch | 99.30% | 0.00% | — | 0.00% / 0.00% | 0.00% |
| Undetected environment drift | 54.23% | 50.85% | 56.88% | 21.85% / 22.00% | 50.85% |
| Mislabeled common-mode errors | 90.42% | 97.17% | 90.15% | 9.75% / 9.40% | 0.00% |

FAR is false accepts divided by all invalid candidates; FRR is false rejects
divided by all valid candidates. Abstentions are not counted as accepts or
rejects. Thus zero FAR/FRR with zero coverage means the system abstained on
everything, not that it correctly classified the stream.

### What the experiment supports

- In the independent-source synthetic scenarios, calibrated fusion reduced
  observed false accepts/rejects relative to uncalibrated majority voting, at
  the cost of abstentions.
- The pairwise dependence audit detected the deliberately correlated
  common-mode scenario: pairwise error phi correlations were approximately
  0.85–0.90. With the gate enabled, the system abstained on all candidates
  instead of multiplying correlated evidence as if independent.
- A declared environment mismatch caused all calibrated evidence to be
  skipped, producing 100% abstention.

### What the experiment does not establish

- It does not establish real protocol accuracy, generalization, or calibrated
  95%/5% operational error rates. One seed and one synthetic generator per
  scenario are not a broad validation campaign.
- Hidden environment drift with a reused environment ID remains a failure.
  In that scenario the calibration rates were high, while evaluation source
  rates degraded to roughly 0.52–0.56. Pairwise error correlation stayed low,
  so the dependence gate did not detect the drift. Accuracy on decided
  candidates fell to 56.88%, with a 21.85% false-accept rate.
- Pairwise phi/Fisher-z auditing can miss nonlinear and time-varying dependence.
  no_large_correlation_detected must not be interpreted as proven independence.
- The environment ID and dataset IDs are user-supplied labels. The software
  does not verify that datasets are actually disjoint or environments truly
  equivalent.
- FAR/FRR observed as zero in a finite test set are not zero population rates.

## Next research step: V0.2.9

The strongest unresolved failure is hidden calibration drift. The next
experiment should use labelled feedback in chronological windows and compare
CUSUM, Page-Hinkley, and ADWIN-style change detectors on source error rates.
A separate no-label track may monitor disagreement and input-feature shifts,
but must only raise a drift warning; without ground truth it cannot assert that
accuracy has degraded. For dependence, test richer joint error models and
conditional mutual-information diagnostics against the pairwise phi baseline.
Do not silently update reliability profiles from unlabelled traffic.
