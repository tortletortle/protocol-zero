# PROTOCOL ZERO V0.2.9 — labelled-feedback reliability drift monitoring

## Scope

V0.2.8 showed that calibration from one environment can become stale when the environment changes but reuses the same environment identifier. Pairwise error-correlation checks do not reliably detect this marginal performance drift.

V0.2.9 adds an **offline, labelled-feedback monitoring layer**. It monitors false-negative and false-positive rates separately for each evidence source. It does not change the CRC solver, frame inference, evidence-fusion policy, or calibration profile. No device I/O, active probing, automatic repair, or automatic recalibration is performed.

## Implementation

New module: `protocol_zero.drift`.

- `LikelihoodCUSUM`: one-sided Bernoulli log-likelihood CUSUM for a predeclared increase in error rate.
- `PageHinkleyIncrease`: one-sided Page-Hinkley mean-shift baseline.
- `HoeffdingWindowDetector`: an ADWIN-inspired split-window baseline with a Hoeffding bound and Bonferroni correction across cuts within one scan. This is **not** the ADWIN algorithm.
- `monitor_source(profile, feedback, ...)`: consumes externally labelled `(ground_truth, source_verdict)` rows, monitors false negatives on valid candidates and false positives on invalid candidates independently, and requires distinct calibration/evaluation IDs plus a matching environment ID.

Calibration error rates use Jeffreys smoothing to avoid zero-probability likelihoods. The default alert policy requires at least two of the three algorithms to signal. These algorithms process the same evidence stream; their agreement is not independent corroboration. Calibration profiles are never updated automatically. Every output retains `integrity_verified=false`.

Default parameters: CUSUM target increase 0.15 and threshold 9; Page-Hinkley delta 0.02 and threshold 10; window min/max 64/2048, per-scan delta 0.01, check interval 16.

## Synthetic benchmark

Reproduce:

```bash
python -m unittest discover -s tests -p 'test_drift.py' -v
python experiments/drift_benchmark.py
```

The benchmark uses 100 paired seeds per scenario, 500 calibration examples per class, and 2,500 sequential labelled evaluation observations per run. The mean smoothed calibration false-negative rate was 0.0510.

| Scenario | CUSUM alarm | Page-Hinkley alarm | Window alarm | 2-of-3 alert | Median 2-of-3 delay |
|---|---:|---:|---:|---:|---:|
| Stationary IID, 5% error | 1% | 0% | 0% | 0% | — |
| Abrupt increase, 5% → 20% | 100% | 100% | 100% | 100% | 75 observations |
| Gradual increase, 5% → 20% | 100% | 100% | 95% | 100% | 576.5 observations |
| Temporary 20% error spike | 100% | 100% | 89% | 100% | 66.5 observations |
| Improvement, 5% → 1% | 1% | 1% | 0% | 1% | — |
| Stationary autocorrelated errors, marginal 5% | 89% | 71% | 0% | 69% | — |

The autocorrelated scenario is a stationary two-state Markov process with the same marginal error probability as calibration. It exposes the main failure: CUSUM and Page-Hinkley treat observations as weakly dependent and alarm on serial clustering even though the marginal error rate has not changed. The 2-of-3 ensemble does not fix this because two algorithms share the same dependence failure.

## Interpretation and limitations

- These are deterministic synthetic experiments, not real protocol captures or field reliability results. One hundred seeds per scenario are exploratory, not a precision estimate of operational false-alarm rates.
- The thresholds are fixed engineering settings, not universally calibrated operating points.
- The Hoeffding correction covers candidate cuts within a single scan only; repeated scans are not time-uniformly corrected.
- The Page-Hinkley and CUSUM alarms are not independent evidence. The 2-of-3 policy is a heuristic.
- A no-alarm result does not establish stable accuracy. Feedback must be labelled by an independently trusted source.
- Environment and dataset IDs are caller-supplied. The module cannot verify that environments truly match or datasets are actually disjoint.
- Only labelled-feedback drift is implemented. Unlabelled feature/disagreement shift may be reported as a warning in a future version, but cannot establish accuracy degradation.
- The inherited full repository test suite was not run in this isolated local harness. Thirteen new V0.2.9 tests passed under Python 3.13.5; compileall passed for the new module, tests, and benchmark. No successful remote CI run or real-device validation is claimed.

## Next step

V0.2.10 should investigate dependence-aware monitoring: block-resampling or run-length-aware calibration, effective sample size, and robust false-alarm evaluation under Markov and burst-correlated errors. It must retain the stationary-autocorrelated null as a mandatory negative control. Do not silently recalibrate from unlabelled traffic.
