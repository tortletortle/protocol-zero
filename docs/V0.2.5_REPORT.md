# V0.2.5 — bounded robust CRC consensus

Base: `907c48f1ccbaabb5b96ace965a2a65012115d432` (V0.2.4). Existing default solver unchanged. New opt-in `protocol_zero.robust_crc` uses NumPy (optional extra `robust`), no API/hardware. For polynomial p, each observed body b and checksum c implies xorout = CRC_p(b, init=0) XOR c XOR T^len(b)(init). Vote for each of 256 initial states; retain all (init,xorout) pairs meeting ceil(0.65*N) distinct-codeword support, grouped by identical behavior. The per-length maximum residual count provides a safe upper bound for pruning. No anchor selection or random sampling. Layout, validation, score and consensus rules match V0.2.4. Completeness applies to voting for a supplied layout within the non-reflected odd CRC-8 family, not arbitrary raw protocols. The 400M vote budget limits counted votes, not wall time or all preprocessing. Budget exhaustion discards partial models. Existing 64 KiB and 4096 model limits also apply.

## Evidence (local execution)

Fresh seeds 85100..85107 in six scenarios (48 additional trials); independent polynomial division generator, 60/40/50 generated train/validation/test frames per trial. Fixed threshold 0.65 for both arms. Clean 8/8 -> 8/8 accepted, 12% bit-flip probability 7/8 -> 8/8, 25% probability 5/8 -> 8/8, 18% mixed deletion/flip probability 7/8 -> 8/8, 45% bit-flip probability 0/8 -> 0/8, unsupported nonlinear checksum 0/8 -> 0/8. All accepted supported cases retained the actual layout and CRC tuple. One false agreed span in mixed case for both versions; all other tested scenarios zero. F1 for mixed 0.873333 -> 0.998333. Other supported fresh scenarios have F1 1 for all accepted trials. No budget exhaustion in these trials. Probabilities are generator settings, not measured exact sample error fractions. Only eight seeds per scenario, no generalization or significance claim.

Failure case mixed seed 85107: true generated frame begins at byte 1005; byte offset 25 (value 0x17) was deleted, leaving 39 bytes through 1044 (exclusive). The following padding 0xb7 yields a 40-byte candidate [1005,1045) that passes the real CRC-8 (poly 0x47, init 105, xorout 233). Both coverage hypotheses agree incorrectly. This is a collision, not evidence that the solver found the wrong polynomial. CRC and model consensus alone cannot certify integrity. No automatic repair. Need independent sequence/boundary or stronger checksums.
