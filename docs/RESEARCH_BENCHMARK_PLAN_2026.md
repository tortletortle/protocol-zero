# PROTOCOL ZERO — 端到端基准与盲测计划（2026-11-23）

## 1. 目标

建立一套能回答“系统究竟有没有分析未知协议”的基准，而不是继续只在自制模拟协议上证明算法有效。

基准必须区分：
- 结构发现：帧边界、字段边界、字段类型；
- 数学关系发现：长度、计数器、校验、跨字段约束；
- 语义推断：字段与真实操作/物理变量的映射；
- 行为推断：消息顺序、方向、状态与转移；
- 工程验证：生成解析器能否在独立数据上正确解析。

任何一个子任务通过，都不能代替完整未知协议逆向通过。

## 2. 四条数据轨道

### Track A — 独立生成的合成协议族

目的：验证每个算法的基本正确性、可辨识边界和模型族外拒绝能力。

每个协议族由独立生成器产生，生成器与识别算法不得共用 CRC/帧切分实现。协议族至少覆盖：
- 固定头、多个同步字、无固定同步字；
- 1/2/4 字节长度字段、不同偏移、大小端、长度偏置；
- 固定长度、变长、嵌套 TLV、多消息族；
- CRC-8/CRC-16、SUM/XOR、自定义校验、无校验；
- 计数器、序号、时间戳、枚举、bitfield、浮点、未知载荷；
- 多方向、多会话、会话内状态依赖；
- 分片、乱序、重复、丢包、突发噪声、比特翻转；
- 压缩、加密、随机负载和模型族外结构。

每个生成实例保存 ground-truth manifest：协议族、字段偏移/位宽/端序/类型、长度与校验规则、消息族、方向、状态转移、生成种子、损坏注入记录。

### Track B — 公开工业 PCAP/PCAPNG

候选数据集：
https://github.com/hi-zer/Industrial-protocols-dataset

初步检查：
- 90 个 PCAP、45 个 PCAPNG；
- 约 25.1 MB；
- 目录中出现 9 个顶层名称，而 README/论文描述为 8 种协议；
- 部分文件名含 run/stop、read/write、upload/download 等操作线索；
- 仓库根目录未发现 LICENSE/COPYING。

因此该数据集是**候选评估语料，不是已经完成授权和 ground-truth 审核的标准基准**。下一步先核对协议目录差异、捕获点、文件标签含义、每条 trace 的设备/方向/操作元数据和再分发许可。未确认许可前不复制数据到 PROTOCOL ZERO 仓库。

使用时必须保留原始文件哈希，不能只记录文件名。

### Track C — 已知公开协议对照

选择具有公开规范/成熟 dissector 的协议，用于后验标注与工具对照，例如 Modbus/TCP、DNP3、S7comm、常见 DHCP/TFTP 等。

注意：这条轨道评估的是“在已知协议族上恢复规范结构”，不能单独证明能分析真正未知协议。训练阶段不得把协议名称、端口、文件名、标准字段偏移或 dissector 输出泄漏给模型。

### Track D — CAN / UART / SDR（独立后续轨道）

- CAN：以报文 ID、DLC、payload、时间戳和独立物理信号标签为基础；评估 bit-level 信号分割与物理语义映射。
- UART：先评估波特率/极性/数据位/奇偶/停止位解码，再评估应用帧边界。
- SDR：先评估调制/符号/线路编码/帧同步恢复，再评估协议层推断。

三者不能混成同一个“原始二进制输入”分数。

## 3. 数据切分与泄漏控制

禁止按 packet 随机切分作为唯一结果。

必须报告：
1. Session-disjoint：同一会话绝不跨训练/验证/测试。
2. Device-disjoint：测试设备在训练中完全不可见。
3. Vendor-disjoint：测试厂商在训练中完全不可见（数据许可和数量允许时）。
4. Protocol-family-disjoint：测试协议族完全不可见，用于真正未知协议拒绝/探索测试。
5. Time/environment-disjoint：不同时间段、不同操作条件或不同采集环境作为留出。
6. Out-of-family：随机字节流、结构化但不支持的协议、加密/压缩流。

对于每条测试记录，必须能追溯其协议族、设备、会话、采集条件和标签来源。若标签来源未知，标记为 unknown，不可补猜。

## 4. 对照系统

同一份数据、同一训练/测试划分、同一资源预算下比较：

| Baseline | 对照范围 | 说明 |
|---|---|---|
| PROTOCOL ZERO main V0.22 | 现有主线能力 | 保留当前能力，不用新算法偷换 baseline |
| Netzob | 格式/字段关系/语法推断 | 记录安装版本、输入预处理、人工操作量 |
| NetPlier | MSA + 概率推断 | 记录 protocol type 参数、评估标签是否参与 |
| Simple statistical baseline | 常量/熵/差分/长度规则 | 判断复杂方法是否真正增加价值 |
| AALpy | 已抽象消息序列上的状态学习 | 单独测状态机，不把它当作 raw-byte parser |
| REInPro/SePanner/Physeinfer/PicaCAN | 论文方法级参考 | 先核实代码/数据/复现条件；无法复现时只列文献对照，不虚构数值 |

不能把论文报告的指标直接横向拼成一个排行榜。不同论文的任务定义、数据划分、指标分母和人工参与程度可能不同。

## 5. 主要指标与定义

### 数据接入
- 可解析记录比例；
- 丢包、重复、冲突和不完整流检测率；
- TCP 重组后的 payload 与参考工具一致率。

### 消息分组与分帧
- 消息族聚类 ARI/NMI；
- boundary precision/recall/F1；
- exact-frame accuracy；
- 对不完整/错位输入的 abstention 与错误接受率。

### 字段
- byte/bit boundary precision/recall/F1；
- 字段宽度与端序准确率；
- 字段类型 macro-F1；
- 计数器/长度/枚举/常量/校验候选的校准表现。

### 校验与关系
- CRC 参数精确匹配率；
- 受支持模型族内召回率；
- 模型族外拒绝率；
- 独立测试消息上的约束违反率；
- 对丢包、噪声、长度变化的稳健性。

### 语义
- 只有存在独立物理/操作标签时才计算 semantic precision/recall/F1；
- 标签必须来自设备日志、HMI、独立传感器或可审计的受控操作记录；
- 仅有相关性时只能报告关联强度与候选排序，不得报告“语义准确率”。

### 状态机
- state/transition precision/recall；
- held-out sequence conformance；
- 状态覆盖率、转移覆盖率；
- 未观测转移与真实非法转移必须区分。

### 可靠性
- false acceptance rate (FAR)；
- false rejection rate (FRR)；
- abstention coverage；
- selective risk；
- 按设备/厂商/协议族分别给置信区间。

## 6. 消融实验

必须分别去掉：
- 消息聚类；
- 多候选保留；
- CRC/长度关系；
- 字段类型候选；
- 语义上下文；
- 时序/因果特征；
- 状态机；
- 主动区分性实验；
- 不确定性拒绝。

目标是证明每个模块对独立留出数据有增量价值，而不是只提高训练集分数。

## 7. 实验流程

1. 冻结数据文件哈希、来源、许可证/授权状态和标签说明。
2. 先定义 ground truth 和切分，再调参。
3. 所有阈值只在训练/验证集选择。
4. 对每个 baseline 记录版本、依赖、预处理、人工配置、运行时间、内存和失败情况。
5. 在盲测集运行，不根据测试结果返工调参后仍沿用同一测试集。
6. 所有结果保存逐样本 JSON/CSV、日志和配置。
7. 失败样本必须保留，尤其是多候选、错误分帧、假语义和模型族外误接受。
8. 任何无法复现的论文结果标记为“文献报告”，不纳入本项目实测分数。

## 8. 分阶段验收门槛

不预先编造一个漂亮的统一准确率。先用 Track A 建立受控可辨识边界，再用 Track B/C 验证真实流量适配性。

- Gate 1：输入重组和数据完整性测试通过，错误/缺失数据不会静默变成完整数据。
- Gate 2：对支持的合成协议族，在独立生成器和全新种子上达到预注册指标；对不支持协议能明确拒绝。
- Gate 3：对公开真实流量，和 Netzob/NetPlier 在同样输入、切分、人工预算下进行可复现实验。
- Gate 4：字段语义只在有独立外部标签时验收。
- Gate 5：状态机在独立会话序列上通过 conformance 测试。
- Gate 6：生成的 dissector/parser 在未参与推断的测试流量上通过 parse/re-encode 或独立解析器一致性测试。

## 9. 本轮后续任务

优先顺序：
1. 审核工业数据集的目录/协议数量差异和授权；
2. 建立 main 与 V0.2.9 的逐模块 API 映射；
3. 定义统一观测/假设/证据 JSON schema；
4. 先跑一个 PCAP 端到端切片与 Netzob/NetPlier 基线；
5. 再决定是否需要新的学习算法。

本计划不授权对生产 PLC、车辆控制总线或无线设备进行主动写入、复位、下载、重放或控制。任何主动查询必须在用户明确授权的隔离实验环境中单独设计。
