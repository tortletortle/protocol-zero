# PROTOCOL ZERO V0.2.6 — CRC collision limits and integrity evidence

## Base and scope

Base branch: research/v025-robust-crc, commit
efa8f43a83e16dbf53453fbfddf9e8c2b4b7b66d.

V0.2.5 improved bounded non-reflected CRC-8 consensus under synthetic corruption, but its held-out report recorded one false agreed span after a payload-byte deletion. A following padding byte completed a CRC-valid candidate. V0.2.6 does not claim to solve this ambiguity. It adds an explicit evidence audit and a constructive indistinguishability witness so downstream code cannot mistake model agreement for integrity verification.

No device I/O, protocol probing, automatic repair, or source changes to the V0.2.5 solver.

## Main result: identical bytes, different histories

For CRC-8 polynomial 0x07, init 0x00, xorout 0x00, the witness uses:

- Header/prefix: AA 55 04 10 20
- Original payload: 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F 10
- Deleted payload byte: index 5, value 06
- Original valid CRC: B7
- Padding byte: 69

Observed byte string:

    AA 55 04 10 20 01 02 03 04 05 07 08 09 0A 0B 0C 0D 0E 0F 10 B7 69

Two interpretations produce exactly this observation:

1. An original valid frame loses payload byte 06; its original CRC B7 shifts left, and padding 69 follows.
2. A different clean frame has payload ending in B7 and CRC 69.

Both clean-frame interpretations satisfy the same CRC-8 model. The raw bytes are identical. A passive algorithm that sees only this byte string cannot determine which history occurred without additional independent information. This is an information limit, not a threshold-tuning problem.

## Uniform-padding null experiment

The experiment uses one fixed known CRC-8 model, a 32-byte random payload, one random deletion position, and one independent uniformly random padding byte.

- Trials: 50,000
- Observed checksum matches: 196
- Observed rate: 0.00392 (0.392%)
- Uniform independent-byte baseline: 1/256 = 0.00390625 (0.390625%)
- Expected matches: 195.3125

This supports the simple one-byte uniform-padding null model. It does not estimate the false-acceptance rate after searching many correlated layouts and CRC models, and it does not represent structured padding or real traffic.

## New API

protocol_zero.integrity adds:

- make_crc8_collision_witness(...): creates the two-history witness.
- crc_collision_baseline(bits): reports the uniform-random checksum-match baseline with its assumptions.
- audit_decode(decoded, model_count): labels unanimous spans as unverified, preserves contested spans, and never emits integrity_verified=True.

The audit output distinguishes:
- model consensus,
- checksum consistency,
- independent integrity evidence (currently absent).

An agreed span is a candidate, not proof of intact transmission, authenticity, or semantic validity.

## Validation

- 7 new integrity tests passed in the isolated local test run.
- The V0.2.5 report previously recorded 51 current tests and 7 legacy tests passing. That complete historical suite was not rerun as part of this isolated V0.2.6 test run.
- The experiment is deterministic under seed 82607 and uses only the Python standard library beyond the existing project CRC implementation.
- No real device captures, hardware, external protocol suite, or remote CI result is claimed.

Reproduce:

    python -m unittest discover -s tests -v
    python experiments/integrity_collision.py --trials 50000 --seed 82607

## Engineering consequence

Do not promote CRC/model consensus to a trusted frame. To distinguish the two histories, a future verifier needs independent evidence, such as an independently observed delimiter, a separately validated payload schema, a stronger independent integrity field, or authenticated framing metadata. Whether any such evidence exists must be established per target protocol; it must not be assumed.

The V0.2.5 solver remains unchanged and available as the baseline.
