# PROTOCOL ZERO V0.2 — Experiment Report

## 1. Research question

Can an integrated byte-stream parser recover variable-length frame boundaries and field hypotheses when captures contain arbitrary leading offsets, inter-frame junk bytes, false sync tokens inside payloads, payload/checksum bit corruption, and occasional byte deletion—while rejecting an unsupported checksum family?

## 2. Method

The prototype searches a bounded model family: 2-byte sync, 1-/2-byte length at relative offsets 2–5, little-/big-endian 2-byte lengths, 0–2 fixed bytes after the length field, a one-byte trailer, and five explicit checksum candidates. Model discovery uses training captures; a separate validation capture gates acceptance; final metrics are computed on disjoint test captures. Both training and validation must meet a minimum checksum-consistency rate of 0.70.

The 0.70 threshold was selected in a separate six-seed pilot (seeds 20100–20105), comparing 0.65 and 0.70. The selection rule chose the highest threshold with at least 90% exact-model recovery in every supported pilot condition and zero acceptance in the unsupported-checksum condition. The confirmatory holdout uses seeds 20400–20419.

Frame selection uses weighted interval scheduling. A frame whose checksum passes is trusted. A structurally plausible frame with a failed checksum is emitted as a suspect, not as a valid decode. Field inference runs only on trusted frames.

## 3. Benchmark protocol

- 5 scenarios × 20 independent seeds = 100 confirmatory runs.
- Per run: 2 training captures × 55 frames; 1 validation capture × 35 frames; 1 test capture × 90 frames.
- Pilot seeds: 20100–20105. Confirmatory test seeds: 20400–20419. Training, validation, and test use disjoint capture seeds within each run.
- `clean`: variable payload lengths and false sync tokens in some payloads.
- `shifted`: random initial capture offset and random inter-frame bytes.
- `noisy`: shifted/gap noise plus a payload/checksum bit flip in approximately 12% of frames.
- `combined`: noisy plus a byte deletion in approximately 2.5% of frames.
- `unknown`: same framing family but checksum generated by an unsupported CRC-8 parameter set.
- Primary metric: exact clean-frame boundary F1. Corrupted frames are not counted as clean truth; suspect precision/recall is reported separately.
- Baselines: restored V0.11 `benchmark.py` no-checksum, greedy-checksum, and DP-checksum modes, fitted on the combined train+validation bytes. Field baseline: restored V0.11 `fields.py` heuristic on the same trusted decoded test frames.
- Paired confidence interval: 5,000-resample bootstrap over the 20 per-scenario paired F1 differences.

## 5. Interpretation

1. Within the tested synthetic family, V0.2 recovered the exact framing model in every clean/shifted run and in 19/20 noisy/combined runs. All accepted runs recovered the uncorrupted frame boundaries exactly.
2. The separate suspect channel isolated bit-corrupted frames with 1.0 precision. In the combined scenario, suspect precision remained 1.0, but recall fell because some byte deletions destroyed or shifted the sync/length evidence needed to locate a frame.
3. V0.2 field inference tolerated sequence gaps caused by missing/corrupted frames by retaining small positive modular-step hypotheses. It does not claim that a counter candidate is semantically a sequence number.
4. Unsupported checksum rejection is a key safety property. A no-checksum parser can produce many plausible-looking but false boundaries.
5. Clean/shifted paired intervals exclude zero; noisy/combined intervals include zero. The current holdout therefore does not establish a statistically reliable frame-F1 improvement in the noisy conditions, despite higher point estimates.
6. The measured gain is specific to the benchmark's protocol generator and supported checksum family. It is not evidence that V0.2 outperforms mature PRE tools on arbitrary network protocols.

## 6. Limitations

- Synthetic byte streams only; no physical UART/CAN/SDR capture was used.
- Only a 2-byte sync word, 1-/2-byte length, payload-length semantics, one-byte trailer, and five checksum candidates are supported.
- The parser flags checksum failures; it does not correct bit errors or reliably reconstruct frames with arbitrary internal insertions/deletions.
- Field confidence values are heuristic evidence scores, not calibrated probabilities.
- No message grammar/state-machine inference or unknown checksum parameter search is included in this release.
- Public tool comparisons are architectural references only; this experiment does not reproduce Netzob, NetPlier, or NEMESYS benchmarks.

## 7. Decision

**V0.2 prototype gate: pass for the bounded synthetic family.**

**General unknown-protocol gate: not passed.** Next work should focus on insertion/deletion alignment, broader length semantics, CRC-16/unknown checksum inference with abstention, public trace evaluation, and real captures.
