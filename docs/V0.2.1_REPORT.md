# PROTOCOL ZERO V0.2.1 — 抗损坏帧重建实验

## 1. 实现及边界
在 V0.2 完整源码包的独立副本上增加 `protocol_zero/repair.py`。V0.2 的分帧、校验和字段推断实现未改动。CLI 增加可选 `--repair`，未开启时仍返回原有数据结构。恢复结果单独输出到 `repair_hypotheses`，`trusted` 始终为 false，不修改抓包文件，不将候选放入原始有效帧或字段学习样本。

范围：相邻两个通过校验的帧之间恰好一个损坏帧，无额外间隔字节，帧头与长度字段完整；最多一次载荷字节插入、删除、位翻转，或者单次校验字节位翻转。支持 V0.2 的五种 8 位校验、1/2 字节长度字段、最大 512 字节载荷。首尾截断、连续多损坏帧、多次编辑、帧头损坏、位滑移不在支持范围。锚点校验通过不证明锚点真实；修复条件不能由观测总是验证。

## 2. 算法
对校验内部状态建立前向向量 F 和从观察校验值反向传播得到的后向向量 R。删除一个载荷字节时逐位置求解连接前后校验状态所需的字节；额外字节通过跳过该状态转移检验；位翻转通过求出的字节与原字节之 XOR 是否为 2 的幂检验。SUM8/XOR8 直接逆运算；三种 CRC-8 使用可逆查表状态转移。每个位置常数时间的状态运算，O(n) 状态运算及 O(n²) 最坏候选材料化空间/时间，不宣称总复杂度线性。去重后保留全部候选。

按已知载荷长度分组，仅在训练和独立验证每组均至少 12 个通过校验的样本、某位置字节在两组都完全相同时，保留该位置的经验常量约束。测试数据不用于学习约束。约束可能失效，不是协议规范；保留约束过滤前、过滤后的候选和样本数。相同长度的不同消息类型并未分组。

首轮试验发现校验字节本身损坏会被误归为载荷损坏。最终版本加入竞争解释：保留载荷、修正单比特校验差异。所有候选仍然不可信，`proposed_hex` 只表示当前有限假设集与经验约束下条件唯一。`payload_only_proposed_hex` 是消融结果，非推荐输出。

## 3. 实验设计
- 探索轮：20 个种子 48000–48019 × 6 个场景，另 10 个集成测试；原始结果 `v021_pilot.json/csv` 保留。此轮用于设计校验字节竞争解释。
- 最终轮：全新种子 49000–49019 × 6 个场景 = 120 个合成捕获；每个捕获 121 帧，其中 60 个指定损坏/对照位置，其间插入正常锚点。训练 200 帧、验证 160 帧，随机源与测试分离；另 10 个不同测试捕获检验完整推断入口。
- 已知模型控制实验随机采样同步字、长度偏移 2/3、1/2 字节长度和端序；五种校验各四个种子。载荷长度取 8/12/16。结构化组所有偶数位置为该长度的确定性常量（刻意高冗余，以验证可恢复性）；随机组所有载荷随机；漂移组损坏帧的第一个常量在测试中发生改变。另设正常帧后填充、双比特载荷损坏、校验字节单比特损坏对照。多数目标有相邻正常锚点，非真实复杂通信分布。
- 模拟器用独立逐位 CRC 实现。主试验提供真实模型，但不提供边界、原文、损坏位置；另 10 个集成试验调用真实模型推断函数。评估以精确观察区间和原始字节完全一致为正确，不把校验通过当作恢复正确。强行选择字典序第一候选、原始候选唯一、经验约束唯一、加入校验竞争解释四种策略共用相同数据。V0.2 原版不输出恢复候选，另报告原版有效帧误接收。

## 4. 最终轮结果（已实际执行）

| 场景 | 试验目标/对照位置 | 无约束唯一正确 | 仅载荷模型+约束正确 | 最终扩展模型正确 | 最终错误候选 |
|---|---:|---:|---:|---:|---:|
| 随机载荷单编辑 | 1200 | 621 | 621 | 615 | 0 |
| 结构化载荷单编辑 | 1200 | 620 | 1107 | 1102 | 0 |
| 结构化约束漂移 | 1200 | 624 | 0 | 0 | 7 |
| 正常帧后填充 | 1200 | 0 | 0 | 0（无修复需求） | 0 |
| 双比特载荷编辑（超出预算） | 1200 | 0 | 0 | 0 | 12 |
| 校验字节位翻转 | 1200 | 0（旧模型之外） | 0 | 690 | 0 |

随机单编辑：条件唯一恢复 615/1200=51.25%，其余 585 个保持歧义；400 个删除字节案例无约束唯一恢复为零。结构化组：1102/1200=91.83%，94 个歧义、4 个未定位；其中删除字节恢复 399/400、额外字节恢复 396/400，剩余为位翻转恢复 307/400。无约束唯一 620/1200=51.67%。仅载荷模型的约束消融配对平均提升 40.58 个百分点，20 个配对种子 bootstrap 5000 次 95% 区间 [37.17,44.17] 个百分点；最终扩展模型另加入校验竞争解释，非同一个消融统计量。结构化组强行取第一候选会产生519个错误。校验字节损坏旧载荷模型加约束产生59个错误候选，扩展模型690个正确、510个歧义、0个错误。

**不能宣称无误修复**：漂移场景7个错误条件唯一候选，全部真实原文均被经验约束过滤；超预算双编辑场景12个错误候选；原版分帧本身在双编辑场景把54个损坏帧误接收为有效帧。最终所有修复候选始终标记为非可信。正常填充对照未发生修复候选，但不能外推至任意噪声。

完整链路：10 个独立捕获中4个推断出正确模型、6个拒绝为歧义；在全部600个损坏目标中恢复232个（38.67%），接受子集232/240=96.67%，无错误条件唯一候选。至少一个拒绝的真实原因已定位：样本长度全小于256时，2字节大端长度的零高位与1字节长度＋固定零字节具有相同解释。不能强行挑选模型；尚未逐个审计全部六次歧义。下一步研究结构等价类及区分性验证。

## 5. 工程验收与复现
Python 3.10+，仅标准库。实际执行 `python -m unittest discover -s tests -v`：16 项通过（V0.2 七项 + 九项新增）。新增候选穷举对照覆盖五种校验，每种8组、每组三种编辑，共120组枚举对照。另历史 V0.11 七项通过，Python compileall 通过。CLI 第一组合法地拒绝歧义；另用 49003 实际运行完整训练/验证/测试，61 个原始有效帧、60 个修复日志、60 个条件唯一候选，全部 `trusted=false`。

在项目根执行：
```
python -m unittest discover -s tests -v
python experiments/repair_benchmark.py
python -m protocol_zero --train train.bin --validation validation.bin --test test.bin --repair --out result.json
```
探索轮回放 `python experiments/repair_benchmark_pilot.py` 写入独立 `v021_pilot_reproduced.*` 文件；使用旧载荷假设的评分字段，示例附带新版诊断。最终原始结果 `experiments/v021_results.json/csv`。V0.2 历史报告、历史实验文件及历史源码保留，不声称已复跑 V0.2 全量100次基准。本轮没执行真实 UART/CAN 捕获或外部工具基准。无 GitHub 写入，本地独立交付。

## 6. 决策
有限单编辑恢复原型通过工程测试；通用自动纠错门禁未通过，不允许把候选自动作为真实数据写回。优先处理观测等价类、校验碰撞、经验规律漂移检测和真实数据；随后扩展 CRC-16。没有证明算法在真实未知协议、一般噪声或成熟开源工具对照下占优。
