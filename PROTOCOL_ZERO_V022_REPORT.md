# PROTOCOL ZERO V0.2.2 — observational equivalence and acquisition planning

## Scope
V0.2.1 archive baseline: `8e7cff25d441fdbec2338df46f75b6b460c6c05f`. Preserve the original single-model API and repair module. New opt-in `python -m protocol_zero.equivalence` enumerates the same bounded model family, groups candidates by identical selected train/validation frame spans, retains every model in near-top groups, reports unanimous spans separately from disputed spans, and proposes independently delimited frame sizes that separate candidate pairs. One-sided tests are conditional on obtaining an actual frame; silence never eliminates a candidate. Three distinct complete frames are required to eliminate based on conflicts; unique status additionally requires zero conflicts and at least three matches for the survivor. No device commands, no automatic repairs, no claim of semantic truth.

## Reproduction
Python 3.10+, stdlib. `python -m unittest discover -s tests -v`; `python experiments/equivalence_benchmark.py`. Initial 62000-series benchmark exceeded the execution limit on long frames and did not save results. The final experiment used fresh seeds 62100–62105, 7 scenarios (42 runs), 36 training and 24 validation frames, 30 separate test frames per run. The old and new decision functions received the same actual `rank_hypotheses` output; checksum memoization was used only during benchmarking and does not change checksum values. All acquisition arms use at most one selected length and three complete frames, with the same data for the same size and seed. The independent checksum generator is reused from V0.2.1. This is a controlled synthetic study, not a real-device benchmark. No external-tool implementation was installed or compared.

## Results
- 26 test methods passed (16 original + 10 new); previous single-model API unchanged for tested cases.
- 30 ambiguous in-family cases: old boundary F1=0, new unanimous boundary F1=1.0; all 30 true structures remained in the active set. Across 36 in-family cases, 1080 test frames recovered, no false unanimous spans. The other six in-family cases were identifiable from initial data; both old and new boundary F1=1.0. Six outside-checksum cases rejected by both.
- Ambiguous cases, one acquisition request: no acquisition 0/30 unique correct, random 7/30, longest 12/30, planner 18/30; 0 wrong unique results for all. In the 12 narrow-length cases, planner and longest received no frame and did not discard the true model. In constructed symmetric-endian cases (6), longest sampled a symmetric length and did not resolve any; planner resolved 6/6 and random 5/6.
- These are descriptive comparisons on six paired seeds per scenario. The scenarios intentionally stress width/endian ambiguity; not a representative population, no formal significance claim. Full raw trial JSON and CSV are packaged separately. The algorithm is not yet integrated with conditional damaged-frame reconstruction; the new path deliberately does not repair under ambiguity.

## Known limitations
Observed equivalence is only agreement on finite captures, not mathematical equivalence over all packets. The score window (0.15) is an inherited heuristic; lower scoring passing groups are visible but are not active, so the true model can be missed. A checksum pass and unanimous boundary do not prove integrity. Acquisition planning considers header/length incompatibility only, not checksum-only differences, and a feasible size must come from a safe authorized experiment; it cannot guarantee the real device will produce a frame. Independently delimited, clean observations are required for elimination: corrupted frames, multiple message types and drift can invalidate this assumption. The conflict threshold is a heuristic, not a calibrated probability. No response never rules out a model. No real captures or hardware were tested. Longer captures can be computationally expensive.

## Reuse review
Netzob: message format and field dependence, suitable future comparative baseline (see https://netzob.readthedocs.io/en/latest/user_guide/inference/vocabular.html and https://github.com/netzob/netzob). AALpy: MIT active automata learning, useful later for authorized protocol state-machine discovery (https://github.com/DES-Lab/AALpy). Neither codebase was incorporated. V0.2.2 is a bounded deterministic length-constraint planner, not state-machine learning.
