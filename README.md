## 目标 / 架构 / 运行方式

目标：从授权采集或模拟的二进制通信记录推断帧结构、校验及字段数学关系，不将统计关联等同于真实语义。

- 分帧与校验：`joint.py`、`calibration.py`、`crc_adapter.py`
- 字段与歧义：`fields.py`、`ambiguity.py`、`dependency.py`
- 关系推断：`relations.py`、`robust.py`、`adaptive.py`、`temporal.py`、`cadence.py`

运行（Python 3，无第三方依赖的 V0.15 实验）：

```bash
python -m unittest discover -v
python evaluate_v15.py
```

V0.15 本地 21 项单元测试通过；800 个实验单元（每种条件 100 个种子，跨块大小配对复用）。负对照中，块大小 1/4/8/16 的逐行置换误报为 5/19/33/42%，分块置换均为 5%；30% 概率整块替换输出的正对照均检出 100/100。原 200 种子实验超时，最终采用 100 种子。详见 `results_v15.json`。

限制：已知正确分帧与块长度、块间可交换且训练验证独立；未验证真实通信数据、未完成端到端集成或第三方工具对照。不将模拟结果外推到真实工业协议。

## V0.16

运行 `python -m unittest discover -q`（27项通过）及 `python evaluate_v16.py`。520组配对模拟实验：固定块320/320长度识别，160/160正对照正确候选检出，0/160负对照误报。200组压力测试中，弱马尔可夫3/40、16周期随机重复1/40出现错误检出。自相关仅扫描1–8阶，阈值为启发式；自动块长度并不证明块间可交换性，只输出探索性证据。种子跨条件复用。尚无真实采集、端到端集成或第三方基准验证。详见 `results_v16.json`。

## V0.17

`python -m unittest discover -q`：32项通过。`python evaluate_v17.py`：250组受控实验（12000条记录），150/150 正确长度候选检出，100/100 负对照无检测，100/150 正对照有多个候选。旧字段模块不支持16位长度标签，不构成公平外部基准。长报文和小端样本并非均为合规 Modbus ADU。

`capture.py` 支持 classic PCAP Ethernet/IPv4/TCP 单段载荷提取，不支持 TCP 流重组、去重、pcapng；`length_rules.py` 需要已分帧记录。第三方测试 PCAP 284字节，Git blob SHA 一致，3条载荷与 MBAP 长度规则吻合，样本不足以盲推断。来源及哈希见 `capture_smoke_v17.json`。外部较大抓包受 DNS 和连接器限制，尚未获取；不能宣称真实工业捕获验证或第三方逆向工具对照完成。

## V0.18

`python -m unittest discover -q`：42项通过。`python evaluate_v18.py`：280组配对训练/验证实验，每条件40个种子；160/160完整流对完全重组并包含正确长度规则及边界，但均存在多候选；80/80缺失或冲突流对被拒绝；40组独立随机字节流负对照中1组误检（seed 19031，规则 offset=7,width=1,bias=7）。旧逐包提取仅在40组对齐样本中完整恢复，120组非对齐样本均不完整。详见 `results_v18.json`。

新增 `stream_reassembly.py` 与 `stream_framing.py`。仅支持 classic PCAP Ethernet/IPv4/TCP，按方向四元组聚合（假设单连接），重组跨度上限1MiB，无SYN时起点未经验证，不能可靠检测尾部丢失或四元组复用。分帧假设完整且起点对齐，搜索偏移0–7、宽度1/2/4、偏差−16至16；最大帧4096字节。生成的类Modbus样本并非真实工业抓包或完全符合规范；种子跨条件配对复用。未完成校验与字段推断端到端集成、真实抓包和第三方基准对照。

## V0.19

`python -m unittest discover -q`：46项通过。`python evaluate_v19.py`：190组受控实验，详见 `results_v19.json`。`pipeline.analyze_pcaps(train, validation, port=None)` 接受训练与验证 PCAP 字节串列表，每个抓包仅允许一个非空、观测到SYN的方向流。输出观测边界等价组、长度规则、固定字节位置、末尾单字节校验候选。保留所有候选，优先选择具有校验证据的组。

90组带校验实验均正确检出目标校验且所有选中规则复现独立测试边界；3组存在不同边界竞争，经校验后剩一个组。30组无有效校验样本均正确分帧且不声明校验，30组随机负对照无候选。另40组 V0.18 风格实验均有多长度规则，仅1组存在不同观测边界；39/40组所有保留规则复现独立测试边界。

限制：种子跨条件复用，校验生成和识别共用实现（另验证标准CRC检查向量）；边界等价仅对已观测数据成立；校验优先策略可能在候选空间外协议失效；一般数学依赖尚未集成，仍假设完整且起点对齐的流，未完成真实工业数据或第三方基准验证。

## V0.20

`python -m unittest discover -q`：54项通过。`python evaluate_v20.py`：120组受控实验，120/120 独立测试流正确且唯一边界，80/80 带校验流通过校验并拒绝单字节损坏，40/40 无校验流明确标记未验证，120/120 末尾单字节截断被拒绝。CRC-8/SMBUS 生成使用独立多项式除法，标准向量 0xF4。详见 `results_v20.json`。

```bash
python pz_cli.py infer train.bin validation.bin protocol.json
python pz_cli.py decode protocol.json test.bin
```

输入是用户提供的完整对齐二进制流；推断可加 `--pcap --port 502` 使用原有 PCAP 单方向流约束。描述文件保留所有候选组及其选择标记、长度规则、校验模型和观测常量。解析时仅使用已选择的假设，重新检查边界，单一校验模型须解释整条流。常量变化仅报告，不硬拒绝。无校验不等于有效；校验通过不等于身份认证。已本地实测 CLI 解析24条模拟报文。仍无真实工业数据、完整字段语义恢复、流式解析或第三方工具对照；完整报文丢失通常无法由长度或校验检测。样本布局固定、种子跨条件配对复用。

## V0.21

`python -m unittest discover -q`：60项通过。`python evaluate_v21.py`：40个随机种子，每种模型共享800个正常及800个异常测试会话。前缀树正常接受0/800、异常标记800/800；单步历史正常接受800/800、异常标记0/800；双步历史两项均800/800。仅正样本验证选深度1，带标签负样本验证选深度2。另有20正常/20异常二进制会话集成测试，事件序列全部恢复，正常全部接受、异常全部标记。详见 `results_v21.json`。

`session_model.py` 为有界历史基线，非新型通用状态机学习算法。输入为外部确定顺序和方向的完整报文段，类型字段偏移需给定。未观测转移不等同于真实协议禁止，正样本无法提供充分的非法行为证据。模拟语法专门需要两步记忆，不代表任意协议。未自动发现消息类型、未实现双向PCAP会话化、未完成真实数据或 AALpy/Netzob/LearnLib 对照。

## V0.22

`python -m unittest discover -q`：65项通过。`python evaluate_v22.py`：160组受控实验，详见 `results_v22.json`。`message_types.py` 在前16个共同字节位置搜索单字节类型候选，通过方向条件边际模型与两步历史模型在验证会话上的平均对数预测增益排序。默认阈值0.2 bit/event、每方向最多16类；不是校准显著性检验。

普通操作码40/40唯一正确，稳定冗余及失效冗余80/80同时保留真实和冗余字段，随机负对照40/40无候选。每个正对照场景使用800正常及800构造异常测试会话；真实字段模型均正确接受和标记800/800；失效冗余字段正常接受0/800，异常标记800/800（无区分能力）。固定模拟布局、配对种子、需要外部提供已分帧方向会话；尚未直接集成原始流、双向PCAP会话化、真实数据或第三方基准验证。保留竞争假设，不将预测关联等同于语义。
